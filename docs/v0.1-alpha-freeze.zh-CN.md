# v0.1 Alpha 发布冻结

v0.1 从今天起不再以“多识别一种思维表达”为发布条件。第一波只承诺在 Codex Desktop 中把一次白板推演可靠保存为一个明确对话作用域的上下文包；项目只是档案位置。只有宿主明确提供当前对话 ID 时，当前宿主才能经 MCP 读取该对话的包。其他宿主仅可作为固定作用域 MCP 的可选读取路径，不作等价交接承诺。

例外：用户以 `this / that / here / there` 或“这个 / 那个 / 这里 / 这边”等方式指代时，系统必须把带时间戳的语言片段、对象或素材区域候选、支撑证据与 `unresolved` 状态保留给主对话。证据不足时应触发澄清，不得静默强绑。

## 可以阻止发布的问题

- 画布服务绑定到错误项目，或跨项目读取、写入、推送数据；
- 一轮推演的画布、事件、录音或导出包丢失、互相覆盖；
- 白板把“主对话已接收”和“主对话已完成处理”混成一个状态；
- 白板根据项目目录、最近任务、历史绑定或旧的 `main-thread.json` 猜测当前主对话并推送；
- 白板把“上下文已注入”说成“主对话已可见回复”或“自动续聊已经发生”；
- 已接收的推送在白板上长期显示“处理中”，让用户误以为仍在传输；
- 录音、截图、转写或白板内容离开当前项目，或没有清楚的本地隐私边界；
- 当前安装候选版本无法完成下方三轮人工验收。

以上问题可以修。与它们无关的新增能力进入发布后的校准清单。

## v0.1 不承诺的事

- 不承诺把圈选、箭头、颜色、停留或手写内容自动理解成确定语义；
- 不承诺把“这个”“这里”“this one”“over here”自动绑定到唯一对象；
- 不承诺英语母语者、其他语言或其他绘图习惯已经得到验证；
- 不承诺画布内 AI 生成、自动教学、BoardScript 回写、PDF/PPT 批阅或 OCR 主流程。

这些信号可以作为带时间和空间坐标的观察证据进入包里。主对话可以据此继续提问、推理和组织输出，但产品不能把候选关系说成已确认的用户意图。

## 发布前的三轮人工验收

验收必须在准备发布的安装版本上进行，不能只跑源码测试。

1. 空白画布推演：直接画一个简单线框，边画边讲，圈选、连线、移动一个对象后结束。确认本轮包完整、白板显示“本轮已整理，可在当前对话继续”、画布未被系统改动；随后由已配置 MCP 的当前宿主读取该轮并自然追问。
2. 图片批阅：导入一张图片，圈两个区域，只口述其中一个；再缩放、平移和移动一个批注后推送。确认未口述的圈仍是未决观察，视图变化没有被写成对象语义。
3. 对话与项目隔离：在同一项目的另一个对话、以及另一个项目中各完成一轮。确认每个已获宿主 ID 的对话只读写自己的作用域；项目只提供归档位置。没有对话 ID 的宿主必须停在显式项目读取，不得伪造自动接续。

三轮都通过，就发布 Alpha。发现的问题按“是否会让用户丢数据、串项目、误解状态或泄露内容”判断是否阻塞；不要因为想补一个更聪明的识别能力而重新打开功能范围。

## 发布后的校准清单

- 手绘圈、箭头、叉号、间距标记与手写标签的候选识别；
- 英语母语者的真实录音和画板样本，先收集同一任务的可比较样本；
- 指代表达与空间动作的绑定评估；
- 在独立样本上评估后，才考虑把候选证据升级为自动解析规则。
