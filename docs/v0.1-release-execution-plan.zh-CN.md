# v0.1 Alpha 发布执行计划

**状态：** 发布前执行中  
**更新：** 2026-07-27  
**唯一发布承诺：** 一次白板思考能留在正确的对话作用域中，项目只作为归档位置，并以固定作用域的上下文包供宿主读取。v0.1 不声明当前可见对话自动注入或自动续聊。

这份计划不扩充识别能力。它把“源码可运行”和“新用户可完成一次工作”分成不同门，任何门未通过都不能以可用 Demo 名义发布。

## 当前事实

- `v0.1.18` 本地候选已纳入源码自动验证、隔离 ASR 的单点转写验证，以及受管 ASR 服务的启动/存活/清理验证；首次安装的 npm 请求已取消非必要审计并设定有界超时，仍需以发布安装包完成真人验收。
- 干净用户空间测试已连续完成两次：无 `node_modules` 的副本从零安装前端和本地 ASR 运行时，冷缓存下载 base 模型后健康端点返回 `faster-whisper/base`，画布运行时身份也指向同一隔离 ASR 地址。第二次同时验证退出后沙箱移入废纸篓、ASR 与画布端口均无残留监听。测试脚本不再额外升级 pip，减少首次安装的一次非必要网络变更，并在安装后执行 `pip check`。
- 这次测试发现冷缓存模型下载可能超过旧的 120 秒等待；旧逻辑会让已打开的画布长期显示“语音准备中”。候选代码现将本地 ASR 就绪检查放在打开画布的门禁内：正常语音会话只在健康端点可用后才打开；纯视觉回合必须显式选择。测试还发现 macOS 后台画布服务会丢失非默认 ASR 端口，导致画布错误回连 `8080`；现已改为显式传递 ASR 运行时身份并有回归测试。异步 ASR 的验收清理也已修复为在退出时再次读取 PID 文件，并由第二次完整烟测证明无残留进程。
- 使用官方 npm registry 的 `npm audit --omit=dev` 曾发现 9 项生产依赖告警（8 中、1 高）。高危 `lodash-es@4.17.21` 经 Excalidraw 的 Mermaid/解析链进入，已以兼容的 `lodash-es@4.18.1` override 消除，并通过完整自动回归。现剩 3 项中危告警，均来自 Excalidraw/nanoid；自动修复要求变更直接 Excalidraw 版本，必须先做画布回归，不能盲跑 `npm audit fix`。
- 尚未完成安装版三轮真人验收，尚未获得公开推送授权。

## 发布门与顺序

### Gate 0｜范围锁定

**目标：** 不用“再聪明一点”延后发布。

- 只修丢数据、串项目、误导状态、隐私边界、首次安装和主对话接续。
- `this / here`、圈画、箭头、光标停驻仅保留为带证据的候选；不把准确率优化重新变成首发条件。
- WorkBuddy、ZCode 等宿主只承诺其已验证的通用 MCP 路径；Codex 只有在宿主明确注入当前对话 ID 时才可使用对话作用域 MCP。独立网页不允许按 workspace、recency 或历史任务猜测当前对话。

**完成证据：** [发布冻结](./v0.1-alpha-freeze.zh-CN.md) 与 README 的边界一致。

### Gate 1｜冷启动运行时

**目标：** 用户不会在画完之后才发现语音或运行时缺失。

| 项目 | 必须证明 | 当前状态 |
| --- | --- | --- |
| 依赖预检 | Node、Python、磁盘、端口和宿主能力可诊断 | 进行中 |
| 首次安装 | 空白用户空间内安装前端、隔离 ASR 与模型缓存 | 连续两次通过，退出无残留 |
| 冷模型下载 | 打开前完成语音就绪门禁；不得误报失败或静默降级 | 模型与端口链路通过；UI真人待验收 |
| 显式降级 | 用户可选择纯视觉回合；包如实标记无转写 | 自动测试通过；真人待验收 |
| 服务复用 | 仅复用健康且兼容的本地 ASR；端口地址传到画布 | 自动测试通过，真人待验收 |

**验收方式：** 运行 `scripts/clean-room-smoke.sh`。它隔离源码副本、`HOME`、模型缓存、项目、端口与本地服务；它不替代不同硬件、不同系统或 Marketplace 安装验证。

### Gate 2｜依赖与隐私供应链

**目标：** 安装发生什么、访问哪里、留下什么，都可提前说明。

1. 对依赖告警逐项归类：生产可达、仅开发可达、可安全升级、需要风险说明。`lodash-es@4.17.21` 高危已通过 `4.18.1` override 修复；剩余 3 项中危项来自 Excalidraw/nanoid，纳入已知风险与后续兼容升级任务。任何新的生产可达高危项必须修复或阻断发布。
2. 锁定 Python 直接依赖、记录模型名称与下载源；安装不隐式升级 pip，完成后执行 `pip check`。模型文件不进 Git，但下载前说明体积、联网和本机缓存位置。
3. 确认所有 ASR、模型、录音和 Prompt Package 都在本机/项目目录；没有原始归档扫描或浏览器转码回退。

**完成证据：** 审计报告、README 依赖矩阵、静态发布检查均为绿色或有明确的已接受例外。

### Gate 3｜安装版主链路

**目标：** 不靠开发目录、已有任务、旧端口或人工补救完成一次工作。

在**准备公开的安装版本**上完成以下三轮：

1. 空白画布推演：画、说、圈、连、移动、结束；确认本轮已保存到正确项目且画布保持原样；随后让当前宿主经 MCP 读取该轮，再输入一个自然的后续问题，确认它能使用该轮上下文继续讨论。
2. 图片批阅：导入图片、只口述部分圈选、改变视图与批注；未口述部分保持未决。
3. 对话与项目隔离：同一项目的两个对话以及第二个项目都独立保存、独立读取、独立路由；没有宿主对话 ID 时仅允许显式项目读取。

每轮同时记录：运行时身份、ASR 状态、画布是否保持原样、同一主对话读取该轮后的回答、是否需要任何人工命令补救。后续回答才证明该宿主在用户可见对话中使用了本轮上下文。

**完成证据：** 三轮安装版验收报告。源码测试、手工读取 JSON、Agent 扫描原始档案均不算替代证据。

### Gate 4｜发布准备

**目标：** 只发布已经证明的范围。

- 执行静态公开检查、完整 `npm run verify`、Skill 校验与 Gate 3 报告。
- 发布说明写明：已验证 macOS arm64；首次 ASR 会下载；Codex 是首发推荐集成，其他宿主为已配置的通用 MCP 路径；任何宿主的自动可见续聊均不作支持承诺。
- 再次确认仓库没有真实录音、快照、转写、`.canvas-prompt` 档案、私有路径或凭证。

**停止条件：** 未得到明确远端推送/发布授权时，只保留本地候选提交，不推送、不提交 Marketplace。

## 执行节奏

1. 先完成 Gate 1 的冷启动状态与 Gate 2 的依赖审计；这是当前唯一会让用户“还没开始思考就卡住”的风险。
2. 再做 Gate 3 的安装版三轮；失败只修对应主链路。
3. Gate 4 通过后才考虑公开推送。

## 本轮明确不做

- 不增加 OCR、PDF/PPT、画布内生成或自动回写。
- 不为了英语、圈画或光标指代准确率推迟 v0.1。
- 不把 WorkBuddy/ZCode 的宿主兼容性表述为自动接续已验证。
